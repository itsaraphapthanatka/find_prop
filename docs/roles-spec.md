# บทบาทและสิทธิ์ 8 ระดับ

> เดิมมี 2 บทบาท (แอดมิน/ลูกทีม) + สวิตช์ "เห็นทรัพย์ทั้งทีม"
> ตอนนี้เป็น 8 บทบาท + **ปิดข้อมูลระดับฟิลด์** + **ขอบเขตตามพื้นที่**
> ติดตั้งด้วย [supabase/roles.sql](../supabase/roles.sql) · ตารางสิทธิ์ฝั่งแอป [src/lib/roles.ts](../src/lib/roles.ts)

กฎที่ใช้ทุกบทบาท:

## "ข้อมูลติดต่อเจ้าของทรัพย์" ที่ถูกปิด = 3 ฟิลด์

`lessor_name` (ชื่อเจ้าของ) · `lessor_company` (บริษัท) · `phone` (เบอร์โทร)

ไม่ปิด: เลขโฉนด · ไฟล์เอกสารแนบ · หมายเหตุ · สถานะ/รูปแบบผู้ติดต่อ · ราคา · ขนาด
(ตกลงกับผู้ใช้ไว้แบบนี้ — ถ้าจะปิดโฉนด/หมายเหตุด้วย เพิ่มใน `properties_view` ได้ทันที)

แทนที่จะเห็นค่าว่างเปล่า บทบาทที่ถูกปิดจะเห็น **ชื่อ + เบอร์โทรของคนที่ลงข้อมูล**
(`created_by_name` / `created_by_phone` — เบอร์มาจาก `profiles.phone` ที่พนักงานกรอกในหน้าโปรไฟล์)
พร้อมข้อความ "🔒 ปิดตามสิทธิ์ของบทบาทคุณ — ติดต่อผู้ลงข้อมูลข้างบนได้เลย"
เพื่อไม่ให้เข้าใจผิดว่า "ทรัพย์ชิ้นนี้ไม่มีข้อมูลเจ้าของ"

## "บ้านเลขที่/เลขที่ห้อง" ที่ถูกปิด = 1 ฟิลด์

`house_no` — ปิดให้ **6 บทบาท** (Associate · Analyst · Survey · Temporary · Social · Trainee)
เหลือเห็นเฉพาะ Owner/Manager และ "ทรัพย์ที่ตัวเองลง"

เหตุผลที่คุมชุดเดียวกับข้อมูลติดต่อ: เลขที่บ้าน + ชื่อโครงการ + แขวง/เขต **ระบุตัวทรัพย์ได้แม่นเท่าที่อยู่เต็ม**
คนที่ไม่ควรเห็นเจ้าของก็ไม่ควรเดินไปหน้าบ้านได้เอง (Trainee ใส่ไว้เพื่อความชัดเจน — เห็นแต่ของตัวเองอยู่แล้ว)

⚠️ แถวนี้ถ้าถูกปิดจะ**ซ่อนแถวไปเลย ไม่ขึ้น "ไม่ได้ระบุ"** — ไม่งั้นอ่านผิดเป็น "ยังไม่ได้กรอกบ้านเลขที่"
(ธง `house_no_masked` จาก view เป็นตัวบอก UI · ที่ดินเปล่าไม่มีแถวนี้ตั้งแต่ต้น)

## "พิกัด" ที่ถูกปิด = 3 ฟิลด์

`lat` · `lng` · `map_url` — **จังหวัด/เขต/แขวง ยังเห็นปกติ** (ไม่งั้นรายการทรัพย์ใช้งานไม่ได้เลย)
หน้ารายละเอียดจะไม่แสดงแผนที่/หมุด และปุ่ม "ดูบนแผนที่" ก็หายไปเอง (เพราะไม่มีพิกัด)

## เขตที่กำหนดให้ (Survey / Temporary)

ตาราง `member_areas` — 1 แถว = 1 ขอบเขต · **จังหวัด** บังคับ, **เขต/อำเภอ** เว้นว่าง = ทั้งจังหวัด
Owner กำหนดจากหน้า **ทีม → คอลัมน์ "เขตที่กำหนด" → + เพิ่มเขต**

⚠️ **ยังไม่กำหนดเขต = ยังไม่เห็นของใครเลย** (Temporary) หรือ **ไม่เห็นพิกัดของใครเลย** (Survey) —
ตั้งใจให้ปิดไว้ก่อนปลอดภัยกว่าเปิดหมด

## ปิดข้อมูลระดับฟิลด์ทำอย่างไร (สำคัญ)

RLS ของ Postgres คุมได้แค่ "แถว" ไม่ใช่ "คอลัมน์" การปิดฟิลด์จึงทำด้วย view:

```
public.properties_view   ← แอปอ่านทรัพย์จากตรงนี้เท่านั้น
   ├─ where can_see_property(...)                        กรองแถวตามบทบาท/เขต
   ├─ case when hide_owner_contact(...) then null end     ปิดชื่อ/บริษัท/เบอร์
   ├─ case when hide_house_no(...) then null end           ปิดบ้านเลขที่/เลขที่ห้อง
   ├─ case when hide_location(...) then null end          ปิด lat/lng/map_url
   └─ contact_masked / house_no_masked / location_masked   ธงบอก UI ว่า "ปิด" ไม่ใช่ "ว่าง"

public.properties         ← เขียน (insert/update/delete) ที่ตารางตามเดิม + policy คุม
```

และที่สำคัญ: **ถอน `select` บนตาราง `properties` ออกจาก `authenticated`**
ไม่งั้นผู้ใช้ยิง REST ตรงๆ (`/rest/v1/properties?select=lessor_name`) ก็เห็นทุกอย่าง = ปิดไม่จริง

> เหลือ `grant select (id, org_id, created_by)` ไว้ 3 คอลัมน์ เพราะ SQL บังคับว่า
> `update/delete ... where id = ?` ต้องมีสิทธิ์ select บนคอลัมน์ที่อยู่ใน where
> ถ้าถอนทั้งหมด ระบบจะแก้/ลบทรัพย์ไม่ได้เลย

ฝั่งแอปจึงต้องอ่านจาก view ทุกที่ — คุมด้วยเทสต์ `npm run test:roles` (ตรวจว่าไม่มีไฟล์ไหน
`select` จากตาราง `properties` ตรงๆ) ปัจจุบันมี 3 จุด: `useProperties.ts` · `FormPage.tsx` · `FollowUpPage.tsx`

## จุดที่บังคับสิทธิ์ (ฐานข้อมูลเป็นตัวตัดสิน)

| ฟังก์ชัน | ใช้ที่ |
|---|---|
| `can_see_property(created_by, org, province, district)` | policy อ่าน + `where` ของ view |
| `can_edit_property(created_by, org)` | policy update · ปุ่ม "แก้ไข" · แผงนัดติดตาม |
| `can_delete_property(created_by, org)` | policy delete · ปุ่ม "ลบ" |
| `hide_owner_contact(created_by)` / `hide_house_no(created_by)` / `hide_location(...)` | คอลัมน์ใน view |
| `in_my_area(province, district)` | Survey/Temporary |
| `can_export()` | ปุ่ม "นำออก" (ฝั่งแอปเช็ค `ROLE_PERM.canExport`) |
| `my_role()` / `is_owner()` / `is_admin()` | ทุก policy ที่เหลือ |

`is_admin()` นิยามใหม่ = **owner + manager** (policy เดิมหลายที่เรียกชื่อนี้อยู่ จึงคงชื่อไว้)
ส่วนงานที่ต้องเป็นเจ้าขององค์กรจริงใช้ `is_owner()` — เชิญทีม · เปลี่ยนบทบาท · กำหนดเขต · นำสมาชิกออก

## การแปลงจากระบบเดิม

| เดิม | ใหม่ |
|---|---|
| `admin` | **owner** |
| `member` | **manager** |
| คำเชิญที่ยังไม่ตอบ (role = member) | manager |
| สวิตช์ `see_all_properties = false` | **ยังมีผล** — จำกัดเป็น "เฉพาะของตัวเอง" ทับบทบาทได้อีกชั้น |

ไม่มีใครเสียสิทธิ์ที่เคยมี (ลูกทีมเดิมเห็นทั้งองค์กร + เพิ่ม/แก้ได้อยู่แล้ว = Manager)
Owner ค่อยลดระดับทีละคนตามจริงภายหลัง

## นำข้อมูลออก (Excel/CSV)

สเปกบอกทุกบทบาทว่า "นำออกไม่ได้" ยกเว้น Owner — แต่ตอนนั้น**ระบบยังไม่มีปุ่มนำออกเลย**
จึงเพิ่มให้ในรอบนี้: หน้ารายการทรัพย์ → ปุ่ม **"นำออก"** (โชว์เฉพาะ Owner)
ได้ CSV ที่ **หัวคอลัมน์เป็นป้ายไทยชุดเดียวกับการนำเข้า** → นำออกแล้วนำเข้ากลับได้ทันที
และนำออกเฉพาะ "รายการที่กรองอยู่" (กรองก่อนแล้วกดนำออกได้)
