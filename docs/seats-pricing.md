# ที่นั่งทีม (seats) — โมเดลราคาแบบลูกผสม

> **ลูกทีมไม่ต้องจ่ายเงินเอง** — องค์กรจ่ายครั้งเดียว ทุกคนในองค์กรได้สิทธิ์ตามแพ็กเกจนั้น
> ที่เปลี่ยนคือ **บิลขององค์กรโตตามขนาดทีม** (เดิมที่นั่งไม่จำกัด = เอเจนซี่ 20 คนจ่ายเท่าคนเดียว)

**1 ที่นั่ง = 1 บัญชีในองค์กร** นับแอดมิน/เจ้าของด้วย และนับคำเชิญที่ยังไม่ตอบรับ
(กันหว่านลิงก์เชิญเกินโควตา — กด "ยกเลิก" ที่คำเชิญเพื่อคืนที่นั่งได้)

## โควตาที่แถมมากับแพ็กเกจ

| ระดับ (โควตาทรัพย์) | Basic (`starter`) | Pro |
|---|---|---|
| 100 ทรัพย์ | 3 ที่นั่ง | 5 ที่นั่ง |
| 250 ทรัพย์ | 5 ที่นั่ง | 10 ที่นั่ง |
| 500 ทรัพย์ | 10 ที่นั่ง | 20 ที่นั่ง |

- **Free** = 1 ที่นั่ง (เจ้าของคนเดียว ไม่มีลูกทีม)
- **Enterprise** = ไม่จำกัด
- **ช่วงทดลองใช้** = ตามแพ็กเกจที่ทดลอง (ทดลอง Pro ไม่มีระดับ → ตีเป็นระดับ 500 = 20 ที่นั่ง)
- ระดับที่ไม่รู้จัก/ยังไม่เคยเลือก (`plan_tier is null`) → ตีเป็นระดับ 500

## ที่นั่งเพิ่ม (ซื้อแยก)

- **฿290/ที่นั่ง/เดือน** หรือ **฿2,958/ที่นั่ง/ปี** (ลด 15%) — ตั้งค่าได้ที่ `app_settings.seats`
- ซื้อได้ครั้งละ 1–50 ที่นั่ง จากหน้า **อัปเกรดแพ็กเกจ → การ์ด "ที่นั่งเพิ่ม"** (`/#/upgrade#seats`)
- ที่นั่งที่ซื้อ **สะสมเพิ่ม** และอายุ **ต่อจากวันหมดอายุเดิม** (`organizations.extra_seats` + `extra_seats_expires_at`)
- ไม่แตะแพ็กเกจ/วันหมดอายุของ subscription — คนละก้อนกัน
- ⚠️ **แพ็กเกจลดชั้น / ที่นั่งเสริมหมดอายุ = เชิญคนใหม่ไม่ได้เท่านั้น ไม่มีใครถูกนำออกจากองค์กร**
  (จำนวนคนอาจเกินโควตาชั่วคราวได้ — หน้าจัดการทีมจะโชว์ว่าเต็ม/เกิน)

## ตัวเลขชุดเดียวกันอยู่ 3 ที่ — แก้ต้องแก้พร้อมกัน

| ที่ | ใช้ทำอะไร |
|---|---|
| [supabase/seats.sql](../supabase/seats.sql) `plan_base_seats()` | **ตัวบังคับจริง** — `create_team_invite` / `accept_invite` เช็คจากตรงนี้ |
| [src/lib/plan.ts](../src/lib/plan.ts) `SEATS_BY_PLAN` | แสดงผล + ปิดปุ่มไม่ให้กดเปล่า |
| [api/_lib/seats.js](../api/_lib/seats.js) `baseSeats()` | ราคาที่นั่ง + ด่านสำรองของ `api/create-member.js` |

`npm run test:seats` ตรวจว่าตัวเลขทั้ง 3 ที่ตรงกัน (grep ไฟล์จริง) — เพี้ยนที่เดียวเทสต์แดง

## จุดที่บังคับโควตา

| จุด | ใคร | ผล |
|---|---|---|
| `create_team_invite()` | คนกดสร้างลิงก์เชิญ | เกิน → error บอกจำนวนที่ใช้/ทั้งหมด |
| `accept_invite()` | ลูกทีมที่กดลิงก์ | เกิน → `org_full` (กันเคสแพ็กเกจลดชั้นหลังส่งลิงก์) |
| `api/create-member.js` | endpoint สร้างบัญชีตรง (แอปไม่เรียกแล้ว) | เกิน → 403 · ถาม `org_seat_limit` จาก DB |
| `my_seat_usage()` | หน้าจัดการทีม | โชว์ "ใช้ x จาก y ที่นั่ง" + แถบสถานะ |

## เส้นทางการซื้อที่นั่ง

```
TeamPage "ซื้อที่นั่งเพิ่ม" → /#/upgrade#seats → createSeatCharge(qty, cycle)
  → api/create-charge.js (plan:'seats')  ยอด = ราคาที่นั่ง × qty  ← คำนวณฝั่งเซิร์ฟเวอร์เท่านั้น
  → PunPay QR → จ่าย → api/verify-charge.js ยืนยันกับ PunPay
  → RPC apply_seat_payment (service-role, กันซ้ำด้วย charge_id) → extra_seats += qty
```

## บั๊กเดิมที่ไฟล์นี้แก้ไปด้วย

`create_team_invite` / `accept_invite` เคยเช็คด้วย `org_is_pro` (= `pro`/`enterprise` เท่านั้น)
ทำให้ org ที่จ่าย **Basic** เชิญคนที่ 3 ไม่ได้ และขึ้นข้อความผิดว่า
*"แพ็กเกจ Free มีลูกทีมได้สูงสุด 2 คน — อัปเกรดเป็น Pro"* — ตอนนี้ใช้โควตาที่นั่งชุดเดียวกันทั้งระบบแล้ว
(`org_is_pro` ยังใช้อยู่กับฟีเจอร์ Pro-only เช่นนัดติดตาม/แผนเยี่ยมชม — อันนั้นถูกต้องแล้ว ไม่แตะ)
